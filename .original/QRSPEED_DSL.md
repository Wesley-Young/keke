# QRSPEED DSL 语法速查

本文根据 `.original/` 目录中的历史 QQ 机器人词库脚本整理，用于后续迁移到 Fraq 时快速理解旧 DSL 的执行模型。这里的“QRSPEED DSL”主要表现为一种“词库/规则脚本”：用触发词或正则匹配消息，然后顺序执行若干行响应、变量赋值、条件判断和内置命令。

## 1. 文件与词库结构

每个 `.txt` 文件基本是一份词库脚本，常见开头为：

```text
&&<配置>兼容模式:是
```

观察到的文件包括 `壳壳功能.txt`、`壳壳娱乐.txt`、`壳壳聊天.txt`、`壳壳群管.txt`、`控制更新.txt` 等。不同文件通常代表不同模块，例如聊天、娱乐、群管、控制更新、特定群专属规则。

脚本由若干“处理块”组成：

```text
[总处理]
如果:$读 群管/%群号%/黑名 %QQ% 0$==1
返回
如果尾
$常调 %参数-1%$

今日老婆
如果:$读 开关/%群号%/开关机 a 0$==0
返回
如果尾
...
```

常见块类型：

| 形式 | 含义 |
| --- | --- |
| `[总处理]` | 全局预处理/过滤器。通常检查黑名单、开关机、模块开关，然后用 `$常调 %参数-1%$` 继续分发当前消息。 |
| `[群].*`、`[好友]签到`、`[临时]签到` | 带消息来源类型的触发规则，常见来源包括群、好友、临时。 |
| `[内部]名称` | 内部回调/子流程，不直接由普通消息触发，通常由 `$调用 ...$` 或 `$回调 ...$` 触发。 |
| 普通文本或正则行 | 一条用户消息触发规则，例如 `今日老婆`、`撤回 ?([0-9]+)`、`@壳壳 .*原神.*`。 |

## 2. 注释与配置

观察到的注释/说明写法：

```text
&&本词库用来控制机器人相关操作！
##游戏大部分为其他大佬的词库
###这里是软件中要加载运行的词库文件
#20-30天
```

其中 `&&<配置>兼容模式:是` 是配置行，不应当当作普通注释删除。`&&`、`##`、`###` 在样本中明显用于注释；单个 `#` 也大量用于人工说明，但是否完全由解释器忽略需要迁移时结合原平台行为确认。

## 3. 触发规则

触发规则通常是一行文本或正则，后面紧跟该规则的执行内容：

```text
壳壳
1:我在
2:在呢
3:啥事
%%随机数1-3%%

撤回 ?([0-9]+)
如果:%括号1%>10
一次性最多只能撤回10条！
返回
如果尾
```

触发表达式特点：

| 写法 | 示例 | 说明 |
| --- | --- | --- |
| 精确文本 | `今日老婆` | 匹配完整命令。 |
| 正则片段 | `撤回 ?([0-9]+)` | 捕获组会写入 `%括号1%`、`%括号2%` 等变量。 |
| 多触发分支 | `微信|@壳壳 微信` | 用 `|` 表示多个可匹配表达式。 |
| 任意匹配 | `@壳壳 .*原神.*` | 使用 `.*`、`[0-9]+`、`[\s\S]*` 等正则语法。 |
| 事件/来源前缀 | `[群].*`、`[好友]签到` | 指定消息来源或内部事件。 |

需要注意：旧 DSL 看起来处于“兼容模式”，触发表达式经常混用普通文本和正则写法。迁移时建议把每条触发显式转换成 Fraq 的命令匹配或正则匹配，不要完全依赖旧平台的隐式规则。

Fraq 对应能力：

| 旧触发写法 | Fraq 建议 |
| --- | --- |
| `今日老婆`、`壳壳` 这类命令 | 用 `ctx.router.command({ name, pattern, execute })`。 |
| `撤回 ?([0-9]+)` 这类参数命令 | 如果是空格分隔命令，优先用 `param.num()`、`param.str()`、`param.greedy()`；如果必须保留旧正则，使用 `ctx.on('message_receive')` 或 `rawPattern + 手动正则`。 |
| `@.* 昵称`、混合 at/图片的输入 | 用 `ctx.router.rawPattern` 和 `param.segment('mention')`、`param.segment('image')`、`param.catchAll()`。 |
| `[群]`、`[好友]`、特定群词库 | 用 `ctx.fork(..., filter.group(...))`、`filter.friend(...)`、`filter.and(...)` 做来源隔离。 |
| 管理员/主人限定触发 | 可以用 `ctx.router.filter`，但官方文档建议部署方可用 `ctx.fork` 加过滤器控制插件可见性；业务内部仍应保留权限 guard。 |

## 4. 执行块与顺序执行

触发命中后，解释器按行顺序执行该触发块内容。

主要行类型：

| 行类型 | 示例 | 含义 |
| --- | --- | --- |
| 普通文本 | `我在！` | 发送文本消息。 |
| 消息段 | `±img=http://...±` | 发送图片、at、shake 等 CQ/消息段。 |
| 变量赋值 | `a:$随机数 0-%c%$` | 计算右侧表达式并赋给左侧变量。 |
| 内置命令 | `$写 path key value$` | 执行平台内置函数。 |
| 条件语句 | `如果:%QQ%==%主人%` | 条件成立时执行直到 `如果尾`。 |
| 流程控制 | `返回`、`$jump :循环$` | 停止当前块或跳转标签。 |

响应行可以连续多行。样本中大量使用 `\n`、`\r` 表示换行：

```text
@%昵称%\n
好的，我将在%括号1%秒后提醒你%括号2%\n
$调用 [%括号1%*1000] 提醒$
```

## 5. 变量语法

变量用 `%变量名%` 引用：

```text
如果:%QQ%==%主人%
@%昵称%
$写 今日老婆/%群号%/时间 %QQ% %时间dd%$
```

常见系统变量：

| 变量 | 含义 |
| --- | --- |
| `%QQ%` | 当前发送者 QQ。 |
| `%昵称%` | 当前发送者昵称。 |
| `%群号%` | 当前群号。 |
| `%群%` | 当前群，常与 `%群号%` 混用。 |
| `%主人%` | 机器人主人 QQ。 |
| `%Robot%` | 机器人自身 QQ。 |
| `%Skey%`、`%Json%` | 登录态或平台提供的扩展数据。 |
| `%AT0%` | 消息中第一个被 at 的 QQ。 |
| `%IMG0%` | 消息中第一张图片。 |
| `%Msgbar%`、`%Msgbar0%` | 消息序号/消息条相关变量，用于撤回等。 |
| `%Time%`、`%NDTime%`、`%RobotRunTime%` | 时间戳或运行时长相关变量。 |
| `%时间dd%`、`%时间HH%`、`%时间HHmm%` | 格式化时间片段。 |
| `%参数-1%` | 当前原始参数/消息文本，常用于 `$常调` 继续分发。 |
| `%参数1%`、`%参数2%` | 参数变量，常见于回调或命令解析。 |
| `%括号1%`、`%括号2%` | 正则捕获组。 |
| `%随机数1-8%` | 随机数快捷变量，表示区间随机。 |

变量名可以是中文、英文、数字组合，例如 `%金%`、`%体%`、`%数%`、`%a%`、`%A%`。

## 6. 赋值语法

赋值使用 `变量名:表达式`：

```text
金:$读 壳壳/%群号%/微壳 %QQ% 0$
a:%随机数2000-5000%
c:[%b%-1]
e:@a[%d%]
```

右侧可以是：

| 右侧形式 | 示例 | 说明 |
| --- | --- | --- |
| 字面量 | `B:0` | 保存字符串或数字。 |
| 变量展开 | `P:%Json%` | 保存已有变量值。 |
| 命令结果 | `a:$访问 https://...$` | 保存内置命令返回值。 |
| 算术表达式 | `C:[%C%+1]` | 用 `[...]` 包裹计算表达式。 |
| JSON 访问 | `e:@a[%d%]` | 从 JSON/数组变量中取值。 |

注意：`1:文本`、`2:文本` 也使用冒号，但语义通常不是变量赋值，而是随机回复候选项。解释器会配合 `%%随机数1-N%%` 选择对应编号行。

## 7. 条件语句

条件写法：

```text
如果:条件
...
如果尾
```

示例：

```text
如果:$读 群管/%群号%/黑名 %QQ% 0$==1
返回
如果尾

如果:%QQ%==%主人%|$读 授权/小主人 %QQ% 0$==%QQ%
主人才可以看到这里
返回
如果尾
```

观察到的条件运算：

| 运算 | 示例 |
| --- | --- |
| 等于 | `%群号%==675710242` |
| 不等于 | `%QQ%!=%主人%` |
| 大于/小于 | `%括号1%>10`、`%数%<%括号1%` |
| 大于等于 | `%时间dd%>=22` |
| 或 | `%参数-1%==草|%参数-1%==哈人` |
| 与 | `%群号%==675710242&$读 授权/群管 %QQ% 0$==%QQ%` |
| 空值判断 | `@A[%B%]==` |

脚本中没有观察到显式 `否则`。常见写法是条件内 `返回`，后面继续写默认分支。

## 8. 返回、调用、回调与跳转

### 返回

`返回` 结束当前触发块，常用于权限失败、开关关闭、命中某个分支后停止执行：

```text
如果:%QQ%!=%主人%
返回
如果尾
```

### 常调

`$常调 %参数-1%$` 常见于 `[总处理]`：

```text
[总处理]
如果:$读 开关/%群号%/开关机 a 0$==0
返回
如果尾
$常调 %参数-1%$
```

推断作用是继续用当前消息内容匹配本词库中的普通规则，相当于“通过总处理后继续分发”。

### 调用

`$调用 延迟 名称$` 用于延迟触发某个内部块或规则：

```text
$调用 2000 一级禁言转盘$

[内部]一级禁言转盘
a:%随机数86400-259200%
$禁 %群号% %AT0% %a%$
```

第一个参数通常是毫秒延迟。也存在动态延迟：

```text
$调用 [%括号1%*1000] 提醒$
```

Fraq 自身提供 `ctx.timeout(fn, ms)` 和 `ctx.interval(fn, ms)`。因此旧 DSL 中的 `$调用 2000 内部块$` 可以迁移成 `ctx.timeout(() => runInternalBlock(...), 2000)`；旧脚本里的循环定时任务可迁移成 `ctx.interval`，并且这些计时任务会在 `Context` 停止时自动清理。

### 回调

`$回调 名称$` 用于切换/触发另一个处理片段，常出现在菜单和多步骤流程：

```text
刷屏检测
开启刷屏检测\r
关闭刷屏检测\r
设置刷屏禁言 时间
$回调 中$
```

如果 `$回调` 只是立即进入另一个内部处理函数，可以迁移成普通函数调用；如果它表示“等待用户下一条输入”的多轮交互，优先使用官方 `@fraqjs/plugin-conversation`。该插件提供 `ctx.conversation.command` 和 `open()`，可以在当前会话中临时注册 `router.rawPattern`，并处理超时和会话冲突，比手写状态机更贴近旧 DSL 的多步骤菜单。

### 标签与跳转

标签使用 `:名称`，跳转使用 `$jump :名称$` 或 `$跳 :名称$`：

```text
A:$获取群列表$
B:0
:循环
如果:@A[%B%]==
$发送$
返回
如果尾
C:@A[%B%]
B:[%B%+1]
$jump :循环$
```

这是旧 DSL 中实现循环的主要方式。迁移到 Fraq 时建议改成普通 `for`/`while`，不要机械保留标签跳转。

## 9. 随机回复

随机回复常用编号行配合 `%%随机数X-Y%%`：

```text
壳壳
1:我在
2:在呢
3:你干嘛
4:啥事
%%随机数1-4%%
```

这表示从编号 `1` 到 `4` 的候选回复中随机选择一条。

也可以把随机数赋给变量：

```text
a:%随机数2000-5000%
d:$随机数 0-%c%$
```

观察到两种随机写法：

| 写法 | 示例 | 说明 |
| --- | --- | --- |
| `%随机数1-8%` | `a:%随机数2000-5000%` | 作为变量展开或快捷随机。 |
| `$随机数 0-%c%$` | `d:$随机数 0-%c%$` | 作为内置命令调用。 |
| `%%随机数1-8%%` | 随机候选选择 | 双百分号用于选择编号响应。 |

Fraq 官方 `@fraqjs/plugin-random` 很适合承接这些功能。它提供 `ctx.random.range(min, max)` 生成闭区间整数，能自然对应 `%随机数1-8%`；提供 `ctx.random.int(min, max)` 生成半开区间整数，适合数组下标；还提供 `pick()`、`shuffle()`、`sample()`、`weightedPick()`，可以直接替代随机回复、随机群成员、抽卡、带权重掉落等旧玩法逻辑。

## 10. 消息段语法

旧脚本用 `±...±` 表示特殊消息段，类似 CQ 码。

常见消息段：

| 消息段 | 示例 | 含义 |
| --- | --- | --- |
| 图片 | `±img=http://example.com/a.jpg±` | 发送图片，值可以是 URL、本地路径或图片文件名。 |
| At | `±at %QQ%±` | at 指定 QQ。 |
| 抖动 | `±shake 1±` | 发送窗口抖动/震动。 |

示例：

```text
@%昵称% ±at %QQ%±\n你今天的群友老婆是:
±img=http://q2.qlogo.cn/headimg_dl?dst_uin=%e%&spec=5±
$群昵称 %群% %e%$(%e%)
```

迁移到 Fraq 时，这类行通常需要改成 Fraq 的消息元素构造，例如文本、图片、at 的组合消息。

Fraq 内置 `msg` 标签模板和 `seg` 命名空间，优先用它们替代 `±...±`：

| 旧消息段 | Fraq 写法 |
| --- | --- |
| 普通文本和变量插值 | `msg\`你好，${nickname}\`` |
| `±at %QQ%±` | `seg.mention(userId)` |
| `±img=http://...±` | `seg.image('http://...')` |
| 表情/回复/语音/视频 | `seg.face(...)`、`seg.reply(...)`、`seg.record(...)`、`seg.video(...)` |

旧 DSL 中连续多行文本、at、图片通常会自动拼成一条回复；迁移时应显式构造消息段数组，例如 `msg\`${seg.mention(userId)}\\n你今天的群友老婆是：${seg.image(url)}\``。

## 11. JSON 与数组访问

旧 DSL 用 `@变量[路径]` 读取 JSON 或数组字段：

```text
A:$获取群成员 %群号%$
B:$JSON 长度 A$
d:$随机数 0-%c%$
e:@A[%d%]
```

也支持多层路径：

```text
P:%Json%
P:@P[pskey]
P:@P[qun.qq.com]

数:@A[data][banned_speak_list]
长:$JSON 长度 数$
账号：@A[data][uin]\n
昵称：@A[data][nick]\n
```

相关内置命令：

```text
$JSON 长度 A$
```

推断用于获取数组或对象长度。迁移时可对应到 JavaScript 的 `array.length`、`Object.keys(obj).length` 或 Fraq 中的 JSON 解析结果。

## 12. 数据读写

`$读` 和 `$写` 是整个词库最频繁的内置命令，用作简易 KV/文件数据库。

```text
金:$读 壳壳/%群号%/微壳 %QQ% 0$
$写 壳壳/%群号%/微壳 %QQ% [%金%+%a%]$
```

推断格式：

```text
$读 路径 键 默认值$
$写 路径 键 值$
```

示例含义：

| 命令 | 含义 |
| --- | --- |
| `$读 群管/%群号%/黑名 %QQ% 0$` | 读取当前群当前用户是否黑名单，默认 `0`。 |
| `$写 授权/群管 %括号1% %括号1%$` | 把某 QQ 写入群管授权表。 |
| `$写 今日老婆/%群号%/时间 %QQ% %时间dd%$` | 记录当前用户今日已抽取。 |

还观察到直接文件操作：

```text
c:$读文件 /storage/emulated/0/QR/QRDic/%QQ%.txt$
$写文件 /storage/emulated/0/QR/QRDic/%QQ%.txt %c%\n\n%括号1%$
$删除 /storage/emulated/0/QR/QRDic/%QQ%.txt$
```

迁移时建议把 `$读/$写` 的路径视为命名空间，而不是实际目录结构。Fraq 官方 `@fraqjs/plugin-kysely` 提供了 SQLite 数据库服务，优先考虑用它承接旧 KV 数据：在插件中注入 `DatabaseService`，通过 `ctx.db.schemas.register()` 注册迁移脚本，再用 `ctx.db.kysely` 做查询、插入、更新、删除。

推荐先实现一个兼容层，把旧命令统一映射为数据库操作：

| 旧命令 | Kysely 兼容层建议 |
| --- | --- |
| `$读 路径 键 默认值$` | 查询 `namespace = 路径`、`key = 键`，不存在时返回默认值。 |
| `$写 路径 键 值$` | upsert 到统一 KV 表，值可以先以 `text` 保存。 |
| `$排行榜 路径 反序 10 ...$` | 查询同一 namespace 下的数据，按数值转换后排序，再格式化。 |
| `$读文件/$写文件` 动态词库 | 如果只是业务数据，也进入 KV/文本表；如果真是插件源码动态加载，不建议原样迁移。 |

`plugin-kysely` 的优势是官方集成、类型安全、支持迁移和事务。像银币变化、礼包领取、每日冷却这类“读后写”的旧逻辑，迁移后最好放进事务，避免并发消息导致数据错乱。

## 13. HTTP 与文本处理

HTTP 访问：

```text
a:$访问 https://api.example.com/path?qq=%QQ%$
A:$访问 SETPOST %A% https://qun.qq.com/cgi-bin/qun_mgr/set_group_admin gc=%群%&ul=%AT0%&op=1&bkn=%B%$
```

观察到 `$访问 URL$` 和 `$访问 SETPOST headers url body$` 两类用法。后者用于带请求头的 POST。

文本处理：

```text
a:$替换 𒑜 %括号1%𒑜$/𒑜***$
a:$取中间 𒑜 %a%𒑜url\":\"𒑜\"$
$URLEncoder %图%$
$转大写 %括号1%$
$转小写 %括号1%$
$数字转中文 %括号1%$
$字符长度 %括号1%$
$随机字符 0123456789 %括号1%$
```

这类命令迁移时基本都可以用 JavaScript 字符串函数、正则、URL 编码和随机函数替代。

## 14. 群管理与 QQ 平台动作

观察到的群/QQ 操作命令：

| 命令 | 示例 | 说明 |
| --- | --- | --- |
| `$禁` | `$禁 %群号% %AT0% %a%$` | 禁言，参数通常是群号、QQ、秒数。 |
| `$踢` | `$踢 %群号% %QQ%$` | 踢出群成员。 |
| `$撤回` | `$撤回 %群号% [%Msgbar%-%数%]$` | 撤回消息。 |
| `$改` | `$改 %群号% %AT0% %括号1%$` | 修改群名片/昵称。 |
| `$全体禁言` | `$全体禁言 %群号% 1$` | 开启/关闭全体禁言。 |
| `$群昵称` | `$群昵称 %群% %e%$` | 获取某人在群里的昵称。 |
| `$获取群成员` | `$获取群成员 %群号%$` | 获取群成员列表。 |
| `$获取群列表` | `$获取群列表$` | 获取机器人加入的群列表。 |
| `$获取群状态` | `$获取群状态 %C%$` | 获取群状态。 |
| `$设置群状态` | `$设置群状态 %群号% ...$` | 修改群相关状态。 |
| `$点赞` | `$点赞 %QQ% 10$` | 给用户点赞。 |
| `$申请群` | `$申请群 %括号1% %括号2%$` | 申请加入群。 |
| `$退出群` | `$退出群 %括号1%$` | 退出群。 |
| `$发送` | `$发送 群 msg %括号1% %括号2%$` | 主动发送消息。 |

迁移到 Fraq 时，这些需要逐一对应到 Fraq/Milky 的事件 API、消息 API、群管理 API。Fraq 文档中推荐通过 `ctx.client` 调用 Milky API，例如获取登录信息、发送群消息回应等；也可以用 `ctx.on('message_receive')`、`ctx.on('message_recall')`、`ctx.on('group_join_request')` 监听原始事件。需要额外处理机器人权限、API 失败返回、风控和异步调用。

## 15. 菜单、卡片与结构化消息

脚本中存在大量 JSON 卡片：

```text
json:{"app":"com.tencent.structmsg","desc":"音乐","view":"music",...}
```

也存在通过变量 `json` 或普通输出发送结构化消息的写法。迁移时应特别注意：

| 旧写法 | 迁移关注点 |
| --- | --- |
| `json:{...}` | 旧 QQ 结构化卡片可能在 NTQQ/Fraq 中不可直接发送。 |
| 音乐卡片 | 需要看 Fraq 是否支持音乐分享元素或只能退化成文本/链接/图片。 |
| 新闻卡片 | 可能需要改成普通链接预览或自定义消息。 |
| 合并转发/聊天记录卡片 | 需要查 Fraq 的 forward/message node 能力。 |

Fraq 官方 `@fraqjs/plugin-takumi` 可以作为卡片降级方案：它能把 JSX 或 HTML 渲染成图片 Buffer，再用 `seg.image(...)` 发送。适合迁移旧菜单、排行榜、状态面板、抽卡结果、资料卡等视觉内容。需要注意 Takumi 不允许直接从网络加载图像资源，远程图片要先下载成 `ArrayBuffer` 并通过 `resourcesOptions.cache` 提供；插件内置 `Noto Sans SC`，中文卡片渲染会比较稳。

## 16. 典型模式

### 全局开关过滤

```text
[总处理]
如果:$读 群管/%群号%/黑名 %QQ% 0$==1
返回
如果尾
如果:$读 开关/%群号%/开关机 a 0$==0
返回
如果尾
如果:$读 开关/%群号%/娱乐系统 a 0$==0
返回
如果尾
$常调 %参数-1%$
```

迁移建议：Fraq 中实现为事件中间件或模块级 guard。来源隔离可以用 `ctx.fork` 搭配 `filter.group()`、`filter.friend()`；模块内的黑名单、开关机、功能开关仍建议封装成 `ensureEnabled(session, feature)` 这类 guard。

### 权限检查

```text
如果:%QQ%!=%主人%
返回
如果尾
```

或者：

```text
如果:$读 授权/小主人 %QQ% 0$==%QQ%
...
返回
如果尾
你不是我的主人，无权操作！
```

迁移建议：封装 `isOwner()`、`isSubOwner()`、`isGroupAdminAuthorized()`。

### 每日冷却

```text
如果:$读 今日老婆/%群号%/时间 %QQ% 0$!=%时间dd%
...
$写 今日老婆/%群号%/时间 %QQ% %时间dd%$
返回
如果尾
```

迁移建议：封装 daily key，例如 `daily:{groupId}:{userId}:{feature}`。

### 从群成员随机抽取

```text
a:$获取群成员 %群号%$
b:$JSON 长度 a$
c:[%b%-1]
d:$随机数 0-%c%$
e:@a[%d%]
```

迁移建议：用 Fraq/Milky API 获取成员列表后，优先用 `@fraqjs/plugin-random` 的 `ctx.random.pick(members)`，而不是直接 `Math.random()`。如果要复现旧玩法或做测试，可以配置固定 seed。

### 排行榜

```text
$排行榜 壳壳/%群号%/银币 反序 10 \n [序号]-[键转昵称%群号%]:[值]$
```

迁移建议：旧 `$排行榜` 同时完成排序、格式化、键转昵称。迁移时需要拆成读取数据、排序、补昵称、格式化输出四步。数据读取和排序可基于 `@fraqjs/plugin-kysely`，普通榜单用 `msg` 发文本即可；复杂榜单可以用 `@fraqjs/plugin-takumi` 渲染成图片。

## 18. 迁移到 Fraq 的建议映射

| 旧 DSL 概念 | Fraq 迁移方向 |
| --- | --- |
| 词库文件 | 拆成 Fraq 插件/模块，例如聊天、娱乐、群管、控制。 |
| `[总处理]` | 模块 guard、`ctx.fork` 事件过滤或统一 pre-handler。 |
| 触发文本/正则 | 优先用 `ctx.router.command`、`ctx.router.rawPattern` 和 `param.*`；旧正则复杂时再手写 matcher。 |
| `%QQ%`、`%群号%` 等系统变量 | 从 Fraq event/message context 中取 `userId`、`groupId`、nickname、mentions、images。 |
| `%括号N%` | 正则 match capture groups。 |
| `$读/$写` | 优先用 `@fraqjs/plugin-kysely` 建 SQLite KV 兼容层。 |
| `$调用 延迟 名称$` | 用 `ctx.timeout`；周期任务用 `ctx.interval`。 |
| `$回调`、多步骤菜单 | 普通函数调用，或用 `@fraqjs/plugin-conversation` 处理等待下一条输入的会话。 |
| `[内部]` | 普通函数、handler helper、conversation 内部 router 或不暴露的 command。 |
| `返回` | handler 中 `return`。 |
| `如果/如果尾` | `if (...) { ... }`。 |
| `:标签`、`$jump` | `for`/`while` 循环或函数递归。 |
| `%随机数...%`、`$随机数`、随机候选 | 用 `@fraqjs/plugin-random` 的 `range()`、`int()`、`pick()`、`weightedPick()`。 |
| `±img=...±`、`±at ...±` | 用 Fraq 内置 `msg` 和 `seg.image()`、`seg.mention()` 等消息段。 |
| JSON 卡片、菜单、排行榜图 | 不支持原 QQ 卡片时，用 `@fraqjs/plugin-takumi` 渲染 JSX/HTML 为图片。 |
| `$禁/$踢/$撤回` | 通过 `ctx.client` 调用 Milky 群管理/消息 API。 |
| `[群]`、`[好友]`、指定群词库 | 用 `ctx.fork` 加 `filter.group()`、`filter.friend()`、`filter.and()`。 |

可优先利用的 Fraq 官方能力：

| 官方能力 | 适合承接的旧 DSL 功能 |
| --- | --- |
| `ctx.router.command/rawPattern/group/filter` | 命令、正则触发、参数解析、权限过滤。 |
| `msg`、`seg` | 文本、at、图片、表情、回复、语音、视频等消息段。 |
| `ctx.on` | 原始事件监听，如撤回、加群申请、非命令消息。 |
| `ctx.client` | Milky API 调用，如发消息、群管理、获取资料。 |
| `ctx.timeout`、`ctx.interval` | 延迟提醒、延迟禁言转盘、周期任务。 |
| `ctx.fork`、`filter` | 按群、好友、管理员、排除群等维度拆模块。 |
| `@fraqjs/plugin-kysely` | `$读/$写`、每日冷却、金币/积分、排行榜、权限表。 |
| `@fraqjs/plugin-random` | 随机回复、随机群成员、抽卡、概率事件、权重掉落。 |
| `@fraqjs/plugin-conversation` | 菜单回调、等待用户输入、交互式配置。 |
| `@fraqjs/plugin-takumi` | 菜单图、排行榜图、抽卡结果图、旧 JSON 卡片降级。 |
| `@fraqjs/plugin-ai` | 旧聊天词库之外的 AI 对话、结构化生成、工具调用；不是迁移必需项。 |

建议迁移顺序：

1. 先安装并接入基础官方能力：`plugin-kysely`、`plugin-random`，按需加 `plugin-conversation`、`plugin-takumi`。
2. 实现旧 DSL 变量、消息段和 `$读/$写` 的兼容 adapter，因为大多数业务逻辑依赖它。
3. 迁移 `[总处理]`，确保黑名单、开关机、模块开关生效，并用 `ctx.fork/filter` 处理群/好友/指定群隔离。
4. 按模块迁移普通触发规则，优先处理高频功能，如聊天、今日老婆、群管命令。
5. 最后处理复杂功能，如排行榜、卡片、HTTP API、动态词库、延迟回调和多轮菜单。

## 19. 迁移时容易踩坑的点

| 风险 | 说明 |
| --- | --- |
| 触发规则边界不明确 | 旧 DSL 里普通文本和正则混用，迁移时要明确是精确匹配、前缀匹配还是正则匹配。 |
| 冒号语义冲突 | `a:...` 是赋值，`1:...` 是随机回复候选，`json:{...}` 是结构化消息变量。 |
| `$常调` 的分发行为 | 它决定 `[总处理]` 后是否继续匹配后续规则，迁移时不能漏。 |
| `$读/$写` 默认值 | 旧命令内置默认值，迁移时读取不存在的数据必须返回同样默认。 |
| 数值与字符串比较 | 旧 DSL 可能自动转换类型，Fraq/JS 迁移时要显式处理数字。 |
| 随机编号回复 | `%%随机数1-N%%` 不是普通随机数输出，而是选择编号候选。 |
| 消息段组合 | 文本、at、图片可能在旧 DSL 中连续多行自动合并，Fraq 中需要明确构造消息数组。 |
| 旧 QQ 卡片 | 结构化 JSON 卡片可能不能在 NTQQ/Fraq 里直接复用。 |
| 群管理权限 | 旧平台命令可能隐式处理权限/失败，Fraq 中要检查机器人权限和 API 返回。 |
| 标签跳转循环 | 直接翻译容易写出难维护代码，建议重构为普通循环。 |

## 20. 最小语法示例

旧 DSL：

```text
今日老婆
如果:$读 今日老婆/%群号%/时间 %QQ% 0$!=%时间dd%
a:$获取群成员 %群号%$
b:$JSON 长度 a$
c:[%b%-1]
d:$随机数 0-%c%$
e:@a[%d%]
±at %QQ%±\n你今天的群友老婆是:
±img=http://q2.qlogo.cn/headimg_dl?dst_uin=%e%&spec=5±
$群昵称 %群% %e%$(%e%)
$写 今日老婆/%群号%/时间 %QQ% %时间dd%$
$写 今日老婆/%群号%/老婆 %QQ% %e%$
返回
如果尾
q:$读 今日老婆/%群号%/老婆 %QQ% 0$
±at %QQ%±\n你今天的群友老婆是:
±img=http://q2.qlogo.cn/headimg_dl?dst_uin=%q%&spec=5±
$群昵称 %群% %q%$(%q%)
```

迁移含义：

1. 当用户发送 `今日老婆` 时触发。
2. 如果今天还没抽过，就获取群成员，随机选一个，发送 at、头像图片和昵称。
3. 写入当天日期和抽取结果作为冷却记录。
4. 如果今天已经抽过，就读取旧结果并再次发送。

这类功能可以在 Fraq 中优先抽象出几个工具函数：`getDailyValue()`、`setDailyValue()`、`pickRandomMember()`、`sendMemberCard()`。
